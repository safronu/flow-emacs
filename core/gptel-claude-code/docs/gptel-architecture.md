# gptel — Architecture Specification

Companion to `gptel-requirements.md` (FR/NFR/P/TC ids cited). Each component states which requirements it serves and why it is built this way rather than another. Baseline: gptel v0.9.9.5 (~17k lines elisp).

## 1. Layering

```
UI:       gptel-transient (menus) · gptel-rewrite · gptel-context UI ·
          gptel-org · gptel-integrations (MCP, vterm)
Chat:     gptel.el — gptel-mode, send command, insertion callbacks,
          persistence, tool-confirmation UI, presets, introspection UI
Core:     gptel-request.el — options, backend/model/tool data model, FSM,
          prompt pipeline, curl+url transports, streaming, logging, schemas
Backends: openai · openai-responses · openai-extras (perplexity/deepseek/
          privategpt/xai) · anthropic · gemini · ollama · kagi · bedrock ·
          gh (Copilot) · oauth + openai-oauth (Codex)
```

*Why:* the core is UI-free and callback-free ("no UI components and no default response callbacks") so third parties can `(require 'gptel-request)` and build other frontends (FR-API, P5). The chat layer supplies default insertion callbacks and everything buffer-ish. Backends are protocol adapters behind `cl-defmethod` dispatch (P4). Optional features load on demand (NFR-1, P6). A separate test repo pins the contracts (§10).

## 2. Core data model

### 2.1 Backend struct
`name host header protocol stream endpoint key models url request-params curl-args coding-system`

- `url`/`header` may be **functions of the request INFO**, evaluated per request — Gemini (URL embeds model+method), Kagi (URL per model), Bedrock (region/model), Copilot (header runs the whole auth machine lazily). *Why:* tokens expire, URLs depend on per-request state; late binding keeps backends declarative (FR-BACKEND-6).
- `key`: string · symbol · function. Resolution: function → call; string → use; symbol → recurse on `symbol-value`; always trim trailing `[\n\r]+`. Default chain ends at auth-source `(:host <backend-host> :user "apikey")` (FR-BACKEND-5). The password prompt on failure is **chat-layer only** (`gptel` command, FR-CHAT-1); `gptel-request` never blocks — it errors when no key resolves.
- `curl-args`: list or function. `coding-system 'binary`: unibyte process/buffer, Bedrock only (FR-NET-5). Default backend also settable declaratively via a `defcustom :set` handler taking `(TYPE NAME . PLIST)` and calling the matching constructor (FR-BACKEND-7, TC-053).
- Concrete backends are subtyped structs (`:include`), registered by name in `gptel--known-backends`; behavior dispatches on struct type (§6). Picker (FR-BACKEND-4) = flat completion over `"backend:model"` strings annotated from model plists.

### 2.2 Models — symbols with plists
Metadata (`:description :capabilities :mime-types :context-window :input-cost :output-cost :cutoff-date :request-params`) lives on the **symbol plist**. *Why not structs:* users must be able to `(setq gptel-model 'gpt-4o)`; a struct would need a second name→object map (FR-BACKEND-3). Consequences: metadata is global per symbol; registering `(name . plist)` **replaces the whole symbol plist** — last registration of a shared name wins. Capability symbols: `media tool-use json url nosystem cache reasoning responses-api audio video` (`audio`/`video` = Gemini media classes, informational alongside `:mime-types`; gates enumerated in FR-BACKEND-3).

### 2.3 Tool struct
`function name description args async category confirm include`; args = plists `(:name :type :description [:optional :enum :items :properties])`; `confirm`: bool or predicate over call args; `include`: t / `call` / nil. Registry `gptel--known-tools` is two-level (category → name → tool) because menu and MCP need category-granular operations (FR-TOOL-1/10, FR-MENU-8).

### 2.4 Request INFO plist
One mutable plist per request through FSM/transports/parsers/callbacks; **the pause/resume token** (dry-run and rejected tool calls resume by handing the same FSM+INFO back). Parsers mutate via `plist-put` on the same head — reference semantics relied on. Minimum callback-author contract: `:data :position :buffer :status`.

| Group | Keys |
|---|---|
| Target | `:buffer` `:position` (start marker) `:tracking-marker` `:context` (opaque caller data — **not** FR-CTX context; unrelated namespace) |
| Payload | `:data` (prompt **buffer** during transforms → payload **plist** after realize; grown in place across tool rounds) |
| Config snapshot | `:backend :model :stream :tools :include-reasoning :transforms :in-place :dry-run :callback` (the system prompt is **not** an INFO key — it lives as buffer-local `gptel-system-prompt` in the prompt buffer) |
| Round state (cleared on each WAIT entry) | `:tool-use :tool-result :error :http-status :reasoning :tokens` — plus `:tool-pending` (set while calls await confirmation; cleared by a chat-layer TOOL handler, not by WAIT) |
| Stream state | `:partial_json :partial_text :reasoning-block` (nil→`in`→t→`done`) `:reasoning-marker :tool-marker :transformer :uuid` |
| Bookkeeping | `:history :status :stop-reason :tokens-full :post :end-time` |

### 2.5 Text-property protocol (the buffer is the database)
Property `gptel`: absent = user · `response` (+`front-sticky (gptel)`) · `ignore` (visible, never sent: reasoning fences, delimiters) · `(tool . ID)` (tool record; ID = provider call-id, **nil for id-less backends** — Gemini/Ollama — where matching keys on tool name, args as tiebreaker; §7.4). Variants use a second front-sticky property `gptel-history` (list of prior strings; session-only, never persisted).

Globally `(gptel . t)` joins `text-property-default-nonsticky`; an `after-change-functions` member re-propertizes insertions **whose end abuts propertized text** (typing before/inside a response) unless at buffer end — typing *after* a response's last char is user text (FR-TRACK-3, TC-022). Cosmetic prefixes are inserted **unpropertized** (start marker moved past them), removed at parse time by literal string trimming.

*Why properties, not prefixes/markers/regexps:* copy-surviving, zero imposed syntax (P2), prompt reconstruction = pure function of buffer content (golden tests). Cost: no file persistence — paid in §9.3. The stickiness scheme is flagged in-source as debatable; TC-022's behaviors are the contract, not the mechanism.

### 2.6 Context model
`gptel-context` (defined in the **core** so presets/API callers can let-bind it without UI): list of file paths · buffers · `(buffer . plist)` · `(path . plist)` with `:overlays` (live overlays), `:bounds` (`(START . END)` char-position cons or list of them, inclusive-exclusive like buffer positions), `:lines` (`(FROM . TO)` 1-indexed cons or list), `:mime` (string). Singleton conses accepted for lists; regions sorted (not merged — overlaps excerpt twice) at excerpt time. (Unrelated to persistence `gptel--bounds`, §9.3.) Buffer regions = overlays via `(make-overlay beg end nil (not advance) advance)`, `evaporate t` + highlight face: region adds (advance=nil) → front-advance t, rear-advance nil — grows at neither edge (TC-112); whole-buffer adds (advance=t) → grows at both ends. Kill-ring context = hidden buffer `" *gptel-kill-ring-context*"` added as whole-content region context; append (prefix arg) rewrites and re-covers it, so overlay growth rules are moot there. File `:lines`/`:bounds` specs are API/preset-level only (no interactive command). Files are plain paths; dead sources pruned lazily at collection (no kill-buffer hooks). *Why overlays (not position lists):* survive edits, self-destruct on deletion, double as the highlight (FR-CTX-2).

## 3. Request finite-state machine

Struct `gptel-fsm`: `state` · `table` (state → alist `(PREDICATE|t . NEXT)`, **first match wins**) · `handlers` (run on state *entry*, get the FSM) · `info`. `gptel-request` **returns the FSM**; `:fsm` accepts a caller-built machine (custom table/handlers) — FR-API-1's pluggable state machine, and how gptel-send/rewrite extend behavior.

Default table (`gptel-request`):
```
INIT ─t→ WAIT ─t→ TYPE ─:error→ ERRS
                    │  ─:tool-use→ TOOL ─t→ TRET ─:error→ ERRS
                    │                          ─:tool-result→ WAIT   (loop)
                    │                          ─t→ DONE
                    └──t→ DONE
ABRT: only via explicit transition from gptel-abort
```
gptel-send inserts TPRE: `TYPE ─:tool-use→ TPRE`, `TPRE ─:error→ ERRS | ─t→ TOOL`. TPRE handlers: token accounting; run `gptel-pre-tool-call-functions` — `:stop` records `:stop-reason`, sets `:status "Stopped by hook"` **and `:error`** (→ERRS); `:confirm`/`:name`/`:args` returns are stashed on the call plists and honored inside TOOL (`:confirm` detected with `plist-member`, so explicit nil suppresses confirmation); `:block` is resolved **inside TPRE itself** — the call's `:result` is set to a `<tool_call_error>`-wrapped string immediately, so blocked calls never reach TOOL processing — then auto-transition. The send set also runs `gptel-post-tool-call-functions` **on TRET entry, before result injection**, plus status updates, insertion prep, `gptel--fsm-last` recording. **Scoping:** tool-call hooks belong to the send/rewrite handler sets; bare `gptel-request` with the default FSM does not run them (opt in via `:fsm`). Rewrite installs its own handler set (§8.3). Predicates are plist lookups (`:error :tool-use :tool-result`); `:error` always listed before `:tool-use`.

**Transition-invocation contract**: handlers and transport code call the transition function explicitly; a state with no pending call is *paused* — the entire pause mechanism.
- Non-streaming: sentinel does WAIT→TYPE, then TYPE→next after parsing.
- Streaming: filter does WAIT→TYPE once the HTTP status line is readable; cleanup sentinel does TYPE→next at stream end (tool-use/error unknowable mid-stream).
- TOOL→TRET fires from the tool-result join: a countdown in the shared continuation transitions when the last (sync or async) result lands. Rejected calls never resolve → FSM rests in TOOL; "continue tool calls" (FR-MENU-8, gated on the buffer's last FSM being in TOOL) re-invokes the TOOL handler on the saved FSM.
- WAIT's handler first clears the per-round keys (same FSM re-fires per tool round; stale `:tool-use`/`:error` would misroute TYPE), then dispatches HTTP and runs `gptel-post-request-hook`.

Every transition pushes the old state onto `:history` (diagnostic view, FR-INSPECT-3). DONE/ERRS/ABRT run the `:post` cleanup list.

**Callback convention** (FR-API-2): `(funcall CALLBACK RESPONSE INFO)`; RESPONSE ∈ string (full/chunk) · `t` (stream OK) · nil (error; read `:status`/`:error`) · `abort` · `(reasoning . TEXT)` / `(reasoning . t)` end · `(tool-call . ((TOOL ARGS CONTINUE-FN)…))` (pending confirmation) — caller runs (or fakes) each tool and invokes CONTINUE-FN with the **computed result string**; the stock confirmation UI does exactly this · `(tool-result . ((TOOL ARGS RESULT)…))`. Callback errors are demoted at every invocation site except the streaming filter's per-chunk calls (NFR-6, §5.5). At DONE, a request that never created a tracking marker (no content) reports " Empty response", inserts nothing (FR-SEND-8).

*Why an FSM (not callback chains):* tool use makes a request a multi-round conversation with branches and async pauses (confirmation, async tools, async transforms); control flow as data buys per-command handler sets, dry-run introspection, pause/resume, a state trail — none of which a callback chain offers.

## 4. Prompt construction pipeline (FR-SEND-3, NFR-4)

`source buffer → prompt buffer (temp copy) → transforms → realize → payload plist`

1. **Prompt buffer**: temp copy of region / text up to point (org: topic narrowing + branching first, §8.4) + buffer-local snapshots of the full request config (~19 variables + `major-mode`). *Why:* transforms get a mutable sandbox (a preset may switch models for this request only); request immune to later edits (NFR-4); `@preset` cookies and oneshot scoping safe by construction.
2. **Transforms** (`gptel-prompt-transform-functions`, default `(apply-preset add-context)`): run in the prompt buffer; sync (0–1 args) or async (2 args: callback+FSM) by `func-arity`; literal `t` splices the global default. `apply-preset` hoisted first (may rewrite the transform list). A completion counter triggers realize after all async transforms (FIXME: should be a chain, §12).
3. **Realize**: resolve directive in the prompt buffer via parse-directive (string / cons of system + template turns inserted at top; function-valued system prompts were already evaluated **in the request buffer before transforms**, at `gptel-request` time, and the resolved value copied into the prompt buffer); drop system for `nosystem`; effective streaming = requested ∧ curl ∧ global ∧ backend ∧ model-not-vetoing; backend `gptel--parse-buffer` walks **backwards** segmenting on the `gptel` property, honoring the turn limit (2 × N messages), trimming prefixes; inject context media into the **first** user message (media can't ride in system messages); `gptel--request-data` builds the payload, params layered global < backend < model via **shallow per-key plist merge, later wins** (FR-BACKEND-8); kill prompt buffer; INIT→WAIT (or stop if dry-run).

## 5. Transport

### 5.1 Registry & abort
`gptel--request-alist`: process → (FSM . abort-closure). Filters/sentinels recover their FSM by process identity — that alone demultiplexes parallel requests (FR-SEND-4). `gptel-abort`: finds the **first** request whose INFO `:buffer` matches, calls callback with `('abort info)`, runs the closure, deregisters, forces ABRT (FR-SEND-5) — both transports; on url-retrieve the closure additionally neuters url's late callback (its transfer can't be killed).

### 5.2 Curl path (default)
- Args: `--disable --location --silent [--compressed] -XPOST -y7200 -Y1 -N -D-` + user + backend extras. `-N` unbuffered (enables streaming), `-D-` headers→stdout, `--location` redirects, `-y7200 -Y1` = 2 h stall timeout (FR-NET-2/3). Proxy travels in the stdin config, not argv: `proxy = "…"` + `proxy-negotiate` + `proxy-user = ":"` lines when `gptel-proxy` is non-empty.
- **Framing token**: per request an MD5 UUID via `--write-out "(UUID . %{size_header})"` — curl appends a `read`-able Lisp cons **after transfer completes**. Consumers: the **non-streaming** parser (splits headers/body by byte count) and the stream-cleanup error path (locates error bodies). The **streaming filter never needs it**: it reads the status line from the first stdout line; stream parsers scan self-delimiting frames (`data:` lines, JSONL, JSON objects, binary frames) directly. The UUID makes `search-backward` from EOB unambiguous within one stream — cross-request demux is process identity (§5.1).
- **Payload via stdin**: process = `curl <args> --config -`; stdin gets a curl config document — repeated `header = "Name: value"` lines, proxy lines (above), `url = "…"`, the write-out line, `data-binary = @-` — then a blank line, then the raw UTF-8 JSON body (`@-` = data from stdin, after the config). *Why (vs argv/temp files):* no argv limits; keys never in the process list (FR-NET-3, NFR-5).
- Coding `utf-8-unix` both ways, no CRLF translation (keeps `size_header` byte-accurate on Windows); `binary` backends get a unibyte buffer — the ASCII trailer still parses.
- Streaming: filter (§5.4) + cleanup sentinel; non-streaming: sentinel parses the accumulated buffer on exit.

### 5.3 url-retrieve fallback
`url-retrieve` POST, same 4-tuple parse contract, split at `url-http-end-of-headers`. Never streams; no proxy/timeout; abort can't kill the transfer (§5.1). Exists for NFR-1/P6 (zero deps); curl is default for streaming, cancellation, redirects, compression, proxies. Exception: Bedrock SigV4 **requires** curl ≥ 8.9 (§7.7) — a scoped, constructor-enforced exception to P6.

### 5.4 Streaming
Backend generic `gptel-curl--parse-stream` runs inside the growing process buffer; **point persists between filter calls**; on incomplete trailing data it rewinds point and returns — the partial frame retries next chunk. Returns this call's text delta; mutates INFO (tool fragments → `:partial_json`, reasoning, usage). Filter layer above: parses the status line once (WAIT→TYPE); demultiplexes reasoning (separate API field or inline `<think>` tags; `:reasoning-block` nil→`in`→t→`done`; text *preceding* `<think>` emitted as response first; assumes a single reasoning block before the answer); invokes the callback per chunk — zero-length chunks dropped pre-callback, so they never create the tracking marker (keeps FR-SEND-8's empty-response detection structural).

Default insertion callback: first chunk → insert `gptel-response-separator` + (chat buffers) response prefix, move start marker past them, create `:tracking-marker` insertion-type t. Each chunk: `goto-char` tracking-marker → optional `:transformer` (md→org; response text only — reasoning has its own marker/wrapping path and bypasses it) → propertize `(gptel response front-sticky (gptel))` → `insert`, all inside `save-excursion`. **User's point never moves and does not follow the stream** — `save-excursion` restores it before the chunk; following is opt-in (`gptel-auto-scroll` on `gptel-post-stream-hook`, `gptel-end-of-response` on `gptel-post-response-functions`) (P3, FR-API-5). At stream end the tracking marker's insertion-type resets to nil.

### 5.5 Errors & logging
Classes (FR-NET-6): curl nonzero exit (message with exit code) · HTTP non-2xx with parseable provider error (probed at `:error`, `:detail`, `:message`, `:Message` — the last for Bedrock) · invalid JSON (curl path: `:error` = "Malformed JSON in response"; url path: `:error` = `"json-read-error"`, the readable text only in `:status`) · else ("Could not parse HTTP response"). url-retrieve failures surface url.el's own error data — no exit codes. Callbacks get nil + INFO `:status`/`:error`; callback calls are wrapped in `with-demoted-errors` at every site **except** the streaming filter's per-chunk calls, which are bare. `gptel-log-level` (nil/`info`/`debug`) appends timestamped JSON to `*gptel-log*` (FR-INSPECT-2). No retries. Known bug: HTTP 100-then-error treated as success (§12).

## 6. Backend abstraction (FR-BACKEND, FR-WIRE)

| Generic | Contract | Default? |
|---|---|---|
| `gptel--parse-buffer (b max-entries)` | prompt buffer → native messages (backward walk on `gptel` property; media links via the mode-dispatched parser when tracking) | none — per backend |
| `gptel--request-data (b prompts)` | messages → payload plist (model, stream, sampling, tools, schema, layered params) | none |
| `gptel--parse-response (b json info)` | non-streaming JSON → text; side effects `:tool-use :reasoning :tokens :stop-reason` + replay of the assistant tool turn into `:data` | none |
| `gptel-curl--parse-stream (b info)` | incremental parse, §5.4 | none |
| `gptel--parse-list (b list)` | alternating-strings template → messages | none |
| `gptel--parse-tools (b tools)` | tool structs → declarations | **yes**: OpenAI `{"type":"function","function":{…}}`, JSON-schema args, `additionalProperties:false` |
| `gptel--parse-tool-results (b results)` | results → provider messages | none (universally divergent) |
| `gptel--inject-prompt (b data msg [pos])` | splice into `:messages`/`:input`/`:contents` | **yes** (OpenAI/Anthropic/Ollama arrays) |
| `gptel--inject-tool-call (b data call new)` | edit a recorded call in the payload (tool-edit UI) | warns "not implemented" |
| `gptel--inject-media (b prompts)` | attach context media to the first user message | warns |
| `gptel--parse-media-links (MODE beg end)` | dispatches on **major mode** (link syntax belongs to the markup) → parts `(:text)` `(:media path :mime)` `(:textfile)` `(:url :mime)` | plain-text default |
| `gptel--parse-schema (b schema)` | structured-output encoding | none — bodyless generic; JSON-capable dialects implement it, and schema-using call sites only occur in backends that do |

*Why cl-generic on structs (not per-backend monoliths):* deviation is per-method — DeepSeek is two `:around` methods over the OpenAI base; xAI is a DeepSeek struct on another host; Copilot delegates every method to an embedded Responses backend per model capability. Inheritance keeps each dialect's diff minimal and testable.

## 7. Wire protocols (normative — exact field names are the contract)

### 7.1 OpenAI Chat Completions — all OpenAI-compatible providers (FR-BACKEND-1)
POST `https://api.openai.com/v1/chat/completions`, `Authorization: Bearer KEY`. Payload: `model, messages[{role: system|user|assistant|tool, content}], stream, stream_options{include_usage:true}` (streaming only), `temperature, max_tokens` (kept for compatible servers), `tools, parallel_tool_calls:true, tool_choice:"required"` (only under force; else omitted → server default), `response_format{type:"json_schema", json_schema{name,schema,strict:true}}`. Multipart user content: `{type:"text"}` / `{type:"image_url", image_url:{url:"data:MIME;base64,…" | "https://…"}}`. Tool replay: assistant message `tool_calls[{type:"function", id, function:{name, arguments:<JSON-string>}}]`; results one `{role:"tool", tool_call_id, content}` per call. Streaming SSE (`data:` lines, `[DONE]`): text `choices[0].delta.content`; tool-call deltas **sequential** at `delta.tool_calls[0]` — non-null `function.name` starts a new call (flushing `:partial_json` into the previous call's arguments); nameless deltas append fragments; the delta `index` field is ignored (OpenAI streams sequentially; caveat for servers that truly interleave). Reasoning: `delta.reasoning` (OpenRouter) / `delta.reasoning_content` (DeepSeek, llama.cpp); non-streaming `message.reasoning` / `message.reasoning_content`. Usage in the last data block: `usage.prompt_tokens/completion_tokens`; cached = `usage.prompt_tokens_details.cached_tokens` or `usage.prompt_cache_hit_tokens` (DeepSeek); input net of cached. Azure: `api-key` header + deployment endpoint. **Quirk (preserve or fix consciously):** the constructor substring-matches host against regexp `"api\.openai\.com"` and silently builds a *Responses* backend — breaks behind proxies (§12).

### 7.2 OpenAI Responses API (FR-WIRE-4)
POST `https://api.openai.com/v1/responses`, Bearer. `input` array: role messages + flat `{type:"function_call", call_id, name, arguments:<JSON-string>}` / `{type:"function_call_output", call_id, output}`. System = top-level `instructions`; `max_output_tokens`; temperature omitted for o-series; **`store:false` — deliberately stateless** (server threads would fight P2). Multipart: `input_text` / `input_image` (bare string URL). Tools flat (no `function` wrapper); force = `tool_choice:"required"`. Schema: `text{format{type:"json_schema", name, schema, strict:true}}`. Streaming event-typed SSE (`event:` + `data:`): `response.output_text.delta` · `response.function_call_arguments.delta` · `response.output_item.done` (finalize a function_call) · `response.reasoning_summary_text.delta`/`response.reasoning.delta` + `.done` · built-in tool completions (web_search, code_interpreter — rendered as notes) · `response.completed` (data wraps the response object: stop reason `.response.status`, usage `.response.usage`) · `error` events **under HTTP 200**. Non-streaming: iterate `output[]` by type (`message` → concat `output_text` parts, `refusal` rendered visibly; `function_call`; `reasoning` → `content[]`/`summary[]` text). Usage both modes: `usage.input_tokens/output_tokens`, cached = `usage.input_tokens_details.cached_tokens`.

### 7.3 Anthropic Messages (FR-WIRE-1)
POST `https://api.anthropic.com/v1/messages`; headers `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-beta: extended-cache-ttl-2025-04-11` (**unconditional**). `max_tokens` **required** (default 4096). System = top-level `system`: string, or content array whose parts carry `cache_control{type:"ephemeral"}` when caching (enabled ∧ model `cache`-capable); cache markers on system parts, the **last** tool, the first block of the **last** message. Content blocks: `text` · `image{source{type:"base64", media_type, data}}` · `document{source{type:"base64", media_type:"application/pdf", data}}` · `tool_use{id,name,input}` · `tool_result{tool_use_id, content:<string; non-strings prin1'd>, is_error:true?}` · `thinking{thinking, signature}`. Tool declarations use `input_schema` (`{}`, never null, for no-arg); force = `tool_choice{type:"any"}`. Tool results ride in a **user** message. Whitespace-only messages skipped (API rejects). Structured output: no native mode — `gptel--parse-schema` returns synthetic tool `response_json`, prepended to `tools` by `gptel--request-data` (**no wire-level forcing**; combine with `gptel-use-tools 'force` for hard forcing); the core unwraps its call (§8.2). Streaming SSE: only `content_block_start/delta/stop` + `message_delta` consumed (`message_start/stop`, `ping` ignored); delta kinds distinguished **by which field is present** — `.delta.text` / `.delta.partial_json` (tool args) / `.delta.thinking` / `.delta.signature`; `content_block_stop` finalizes pending JSON/reasoning; `message_delta` carries `stop_reason` + usage. Thinking signatures replayed verbatim with the block. Usage: `input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens`.

### 7.4 Gemini (FR-WIRE-2)
Host `generativelanguage.googleapis.com`; URL/request: `https://{host}/v1beta/models/{model}:{streamGenerateContent|generateContent}` (suffix per effective streaming); header `X-goog-api-key`. Roles `user`/`model`; `contents[].parts[]`: `text` · `inline_data{mime_type,data}` · `functionCall{name,args}` · `functionResponse{name, response{name,content}}`. System = `systemInstruction{parts[{text}]}`. `safetySettings` hardwired, no user knob: `HARM_CATEGORY_{HARASSMENT, SEXUALLY_EXPLICIT, DANGEROUS_CONTENT, HATE_SPEECH}` all `BLOCK_NONE`. Sampling under `generationConfig` (incl. `thinkingConfig{includeThoughts:true}`, `responseMimeType:"application/json"` + `responseSchema`); schemas get `additionalProperties` **recursively stripped**; no-arg tools need `parameters:null` (Anthropic's inverse). Tools: `[{functionDeclarations:[{name,description,parameters}]}]`; force = `toolConfig{functionCallingConfig{mode:"ANY"}}`. **No tool-call ids**: `:tool-use` entries carry `(:name :args)` only, buffer records get nil ID; replay/edit matching keys on name (args tiebreaker) — parallel same-name calls ambiguous (inherited limitation; Ollama shares it — §12). Streaming: **incrementally delivered JSON array** — scan for `{`, `json-read` each complete object (rewind on incomplete), feed through the non-streaming parser. Reasoning: text parts flagged `thought:true`. Usage: `usageMetadata.promptTokenCount`, output = `totalTokenCount − prompt`, cached = `cachedContentTokenCount`.

### 7.5 Ollama (FR-BACKEND-1)
POST `http://localhost:11434/api/chat`, no auth by default (constructor still accepts optional `:key`/`:header` for proxies). ### 7.7 AWS Bedrock — Converse/ConverseStream (FR-WIRE-6)
URL `https://bedrock-runtime.{region}.amazonaws.com/model/{model-id}/converse[-stream]`; friendly symbols map through a fixed table to Bedrock ids (e.g. `claude-sonnet-4-5-…` → `anthropic.claude-sonnet-4-5-…-v1:0`), optionally prefixed by the `:model-region` inference profile (`us.`/`eu.`/`apac.`/`global.`). Credentials: `$AWS_ACCESS_KEY_ID`/`$AWS_SECRET_ACCESS_KEY`/`$AWS_SESSION_TOKEN`, or `aws configure export-credentials [--profile <:aws-profile|$AWS_PROFILE>]`, cached in memory per profile with expiry-aware refresh. *Why curl-SigV4 (not elisp):* crypto correctness outsourced; hard version gate accepted (§11). Payload: `messages[].content[]` blocks `text` · `image{format:"png|jpeg|gif|webp", source{bytes:<b64>}}` · `document{format, name, source{bytes}}` · `toolUse{toolUseId,name,input}` · `toolResult{toolUseId, status:"success"|"error", content:[{text}]}`; `inferenceConfig{maxTokens}`; `system:[{text}…]`; caching = `cachePoint{type:"default"}` blocks after the system text and at the end of the tools array (same `gptel-cache` option — FR-WIRE-1; message-level cache points deliberately not emitted); tools `toolSpec{name, description, inputSchema{json:<generic OpenAI parameters schema>}}` under `toolConfig`, whose `toolChoice` is always sent — intended `{any:{}}` under force, else `{auto:{}}`; the reference implementation has a stray-quote bug that actually emits `{"any":{"quote":{}}}`/`{"auto":{"quote":{}}}` (§12). Streaming: binary `application/vnd.amazon.eventstream` — frame = 12-byte prelude (int32 BE total length · int32 BE headers length · 4-byte prelude CRC), headers section, JSON payload (length = total − prelude − headers − 4), 4-byte message CRC (CRCs deliberately unvalidated). Header encoding as read: 1-byte name length · name · 1-byte value type · 2-byte value length (always read; consulted only for variable-width types) · value; widths by type: 0 true / 1 false = 0 bytes; 2 int8 = 1; 3 int16 = 2; 4 int32 = 4; 5 int64 = 8; 6 bytes / 7 utf8-string = value-length; 8 timestamp = 8; 9 uuid = 16; big-endian. In practice Bedrock's headers (`:event-type`, `:content-type`, `:message-type`) are utf8 strings; the event name lives in `:event-type`. Events: `messageStart` · `contentBlockStart` (may carry `toolUse{toolUseId,name}`) · `contentBlockDelta` (`.delta.text` | `.delta.toolUse.input` fragments) · `contentBlockStop` · `messageStop` (`stopReason`) · `metadata` (`usage{inputTokens, outputTokens, cacheReadInputTokens, cacheWriteInputTokens}`); blocks correlated by `contentBlockIndex`. Streaming reasoning currently discarded (§12).

## 8. Subsystems

### 8.1 Context (FR-CTX)
Variable in the core (§2.6); commands/formatter in `gptel-context.el`; injection = the default `add-context` prompt transform. Collection normalizes, prunes dead sources, expands directories (memoized `project-files`, `.gitignore`-respecting, remote paths exempt — FR-CTX-4), reads regions under `without-restriction` (narrowing-immune, TC-120). Serialization: `Request context:\n\n` + per source ``In buffer `NAME`:`` / ``In file `~/path`:`` (backtick-quoted names) + ``` fence (buffers: info-string = major-mode name minus `-mode`, e.g. `emacs-lisp`; files: bare fence), `... (Line N)` discontinuity markers, leading `...` for mid-line starts, trailing `...` short of EOB (TC-118); formatter replaceable, possibly async (arity-sniffed). Injection: prepend to system prompt (string / function — parsed first / cons — fresh-cons prepend), or splice before the final user text (search back for last unpropertized segment); `nosystem` auto-falls back to user. Media context bypasses the string path → `gptel--inject-media` into the first user message. Inspector: `special-mode` render, chunk overlays pointing at sources; two-phase deletion (flag → confirm) because the buffer is read-only and batch removal should be reviewable (FR-CTX-7).

### 8.2 Tools & MCP (FR-TOOL)
Parsers record calls in `:tool-use` **and** replay the assistant turn into `:data`. TPRE (send flow) runs `gptel-pre-tool-call-functions` (§3). TOOL handler: resolves confirmation — hook-set `:confirm` on the call plist > global `gptel-confirm-tool-calls` (t/nil) > tool's `confirm` slot (predicate on args) under `auto` — and special-cases the ersatz tool: a call named `response_json` is **unwrapped in place** — args JSON-encoded → callback as the response (+ `t` when streaming), call removed from `:tool-use`; no confirmation, no result round-trip, no further transition from that branch (caller already has the full response). Unknown tool names → error-string result listing available tools. Sync tools in `condition-case` (errors → string results); async tools get the continuation prepended; a countdown joins parallel results, fires TOOL→TRET (§3). TRET injects `gptel--parse-tool-results` output, loops to WAIT.

Confirmation UI (chat layer): in-buffer read-only block — `(tool_name "arg" …)` truncated header per call, banner "Run tools: C-c C-c, Cancel request: C-c C-k, Inspect or Edit: C-c C-i", mouse dispatch via `read-multiple-choice` — or minibuffer choice (forced for read-only buffers). Inspect buffer maps overlays to call indexes; edited plists re-`read` and propagated via `gptel--inject-tool-call`; deleting a call's text drops it. Hook plist protocol (both hooks): input `(:name :args :buffer :backend :model [:result])`; returns `:stop` · `:stop-reason` · `:block` (t or error string for the LLM) · `:confirm` · `:args` · `:name` (rewrites propagate to execution **and** history) · `:result` (post: replaces what is sent and shown).

In-buffer records (FR-TOOL-8): org `#+begin_tool <truncated call>` / markdown ```` ``` tool <truncated call> ```` (space after the fence) blocks; body = plist `(:name NAME :args ARGS)` + blank line + result, propertized `(tool . ID)` (delimiters `ignore`), auto-folded; include=`call` replays the literal string `"(Cached tool result — available during original generation but not replayed)"`. *Why in-buffer records (not hidden tables):* saved chats replay tool turns from text alone (P2).

MCP: tools registered under category `mcp-<server>` — idempotent registration, exact disconnect, automatic menu grouping; connect starts servers as needed, registers **and pushes onto global `gptel-tools`** (activation), reports partial failures; disconnect removes category + selection, offers server shutdown.

### 8.3 Rewrite (FR-RW)
A consumer of the core proving its generality: own FSM handler set — overlay status updates layered on the standard tool-state handlers (TPRE/TOOL/TRET, so tool-call hooks fire here too, FR-TOOL-9) — own callback, `:context` = (overlay . staging-buffer). Prompt = 3 turns: region text (or, iterating, the pending rewrite output) · canned assistant turn `"What is the required change?  I will generate only the final replacement."` (authoritative, two spaces) · the instruction. Directive: variable seeded from `gptel-directives`' `rewrite` entry; default runs `gptel-rewrite-directives-hook` (first non-nil) → mode-derived template; menu/alist selection replaces at scope. `nosystem`: directive prepended to the first prompt element; context moved to the user channel (rewrite's context default is `system`).

Response staged in a hidden buffer: original text as a shadow-faced placeholder consumed as chunks arrive; `major-mode` **variable set without running the mode** (mode hooks in temp buffers caused breakage; only font-lock wanted); projected onto the region via the overlay's `display` property → live morphing preview, buffer unmodified until accept (undo, `buffer-modified-p`, concurrent edits honest — FR-RW-3). Overlay: status before-string (REWRITE · state · model, right-aligned), priority 2000, keymap, evaporate. On success: trailing newline restored if the original had one; source buffer's `gptel-post-rewrite-functions` run **in the staging buffer**; final string stored as the overlay payload; eldoc + help-echo hints. Actions (keymap or `read-multiple-choice` dispatch — default-action `dispatch` opens that chooser; default nil = wait): accept (insert payload over region) · reject (delete overlay) · iterate (input = pending output, instruction pre-filled) · diff/ediff (buffer copy with rewrites applied; ediff stashes overlay `display`/`face`, restores them + window config on quit) · merge (`git merge-file --no-diff3`, labels original/<backend>, when git exists; manual `<<<<<<<` markers fallback, forced to BOL; `smerge-mode` on). The no-region menu carries batch variants, diff switches, navigation. Abort/error paths delete overlay + staging buffer; a killed source buffer makes the callback no-op harmlessly (its body is guarded on a live `overlay-buffer`), so no error — but no active cleanup either.

### 8.4 Org support (FR-ORG)
- **Prompt**: org sent as org (P1). Copier order: region narrowing (region wins) → GPTEL_TOPIC narrowing (subtree of the property-inheriting heading) → branching **within**: outline lineage of point — each ancestor's heading + body to its first child, deepest heading's body to point/prompt-end; lineage positions before `point-min` dropped; leading non-heading text included (hence "heading at point-min excluded unless point under it", TC-174). Then strip gptel's `#+begin_tool`/`#+begin_reasoning` header lines (anti-mimicry), strip `gptel-org-ignore-elements` (default `(property-drawer)`, fast regex; full org-element parse "too slow" — NFR-7), unescape tool blocks. Branching org-only (Org ≥ 9.7 lineage primitives; warn + linear below). Heading-shaped prompt prefixes (default `*** `) make successive prompts siblings = separate branches — use non-heading prefixes with branching (FR-ORG-3).
- **Config**: per-heading `GPTEL_*` properties = dynamic overrides — `:around` advice on the send commands let-binds inherited properties for exactly one request, composing with buffer-locals via `or`. Encodings: `GPTEL_SYSTEM` `\n`-escaped; `GPTEL_TOOLS`/`GPTEL_PRESET` space-separated names; numbers parsed. `GPTEL_PRESET` rides into the prompt copy, applied there with the full preset machinery (buffer-locally) — hence beats `GPTEL_SYSTEM`. *Why advice+let (not setq-local):* one-request scope that wins over buffer state without persisting.
- **Response**: md→org. One-shot regex converter for full responses; streams get a **stateful closure per response**: accumulation buffer, block state (fence-width countdown, literal-`#+begin_src` passthrough), withhold pointer — lexemes ambiguous at chunk end (partial backtick run, `#`, trailing `*`) held back and re-scanned. Correctness = byte-identical output under all chunkings (tests). Emphasis conversion suppressed inside code blocks. Cleanup keyed by the response's start marker → concurrent streams safe. *(Why not convert-at-end: chunking invariance while streaming.)*
- **Persistence**: `GPTEL_BOUNDS` written with a marker-checked retry loop (writing shifts the offsets being written; ≤ 6 iterations, then best-effort), `print-length` bound to nil (truncation once corrupted long lists).

### 8.5 Presets & scoping (FR-PRESET, FR-MENU-2)
`gptel--set-with-scope`: global (kill any local binding first so global visibly wins) · buffer-local · oneshot — save the old value on the symbol plist **only if none already saved** (nested oneshots keep the true original, TC-071), restore via a self-removing `gptel-post-request-hook` member deferred with `run-at-time 0` (*why:* the hook can fire inside a let of the same variable). Restore fires right after the next request **dispatches** (payload already realized), not at completion; two overlapping oneshots on one variable → first dispatch restores (accepted simplification; payloads unaffected, NFR-4). Presets map `:foo` → `gptel-foo`, else `gptel--foo` (public preferred); applied through a caller-supplied setter: plain elisp = global `set` · menu = scope-aware · `@cookie` = buffer-local **in the prompt copy** (per-request) · `gptel-with-preset` = let-binding. The `@name` cookie is scanned only after the last `response` property (final user turn), removed from the sent text. Drift indicator: fast field-by-field comparison of preset spec vs current values (function-valued entries skipped — imperfect by design).

### 8.6 Transient UI (FR-MENU)
One shared scope infix across all menus. The one-shot "additional instruction" (FR-MENU-1) is a transient arg, never a variable: while set, an overlay labeled `DIRECTIVE:` previews it in the work buffer (cleared on menu exit); at send it merges into the system prompt for that request only, joined with a blank line (string → appended; list → appended to the car; function → wrapped lazily). Crowdsourced-prompt picker (FR-MENU-7): CSV fetched once per 14 days after explicit consent, cached on disk, chosen prompt always routed through the directive editor ("pick and edit", never applied blind); quitting its completion exits the whole menu (accepted quirk). Tool menu stores selection state in the prefix's **scope plist** (transient args reflect only visible suffixes; hidden-category selections must survive). Category key three-state: not shown → show; shown ∧ ≥1 selected → deselect all; shown ∧ none → select all. Send suffix renders a live English description of source/context/destination from pre-export transient state (the behavior, FR-MENU-5, is the requirement — not the internals hack). Incompatibility groups: prompt-source flags `(m y i)`, destination flags `(e g b k)` (FR-MENU-3/4). Dynamic key assignment: first free character of the item name from an ordered pool; reserved: `s` (directives), `q`/`M` (tools), `mcp-` prefix ignored for mnemonics. Redirection: one send engine consumes the flags; prompts routed into other sessions fenced in the *target's* markup; in-place kills the prompt (region, or text after the last response boundary), recording it as response history. Key rebinding = Transient's `transient-suffix-put` (FR-MENU-11).

### 8.7 Introspection (FR-INSPECT)
Dry-run returns the parked FSM; the viewer renders `:data` (Lisp/JSON), re-`read`s edits back, resumes via the normal INIT→WAIT transition — no special send path. The curl-command exporter uses an argv-style arg builder kept only for this. FSM inspector renders INFO + `:history`; `:data` message bodies scrubbed unless logging (NFR-5).

### 8.8 Chat-buffer UI & media annotation (FR-CHAT, FR-MEDIA)
`gptel-mode` wiring (§9.5) plus: header line, right side pixel-aligned (`string-pixel-width`), clickable segments — status (→ FSM inspector) · token usage (buffer-local pair of plists, last-request + session cumulative, summed per response; rendered `[Nk↑, CNk↑ N↓]`, click toggles request/session — FR-CHAT-5) · `[N tools]` (→ tool menu) · `[Media: Send/No]` (media-capable models only; toggling reruns link annotation) · context counts (→ inspector) · system-prompt preview (→ directive menu) · model (→ menu). Header line off: `mode-line-process` + echo messages. Fence folding: TAB on a fence line (keymap text property) hides the body with an invisible overlay + `"..."`; nesting by fence parity (FR-CHAT-6). Media links: per-mode jit-lock functions keep one annotation overlay per link outside responses (`before-string` "SEND" or red "!", `help-echo` = failure reason, priority −80, evaporate); validation: link type (file/attachment; http(s)/ftp only for `url`-capable models) → per-mode user predicate → readability → binary MIME vs model capabilities, memoized per path (FR-MEDIA-2/3).

### 8.9 Public API surface (FR-API)
`gptel-request (&optional prompt &key callback buffer position context dry-run stream in-place system schema transforms fsm)` — prompt: string · alternating user/LLM turn list · structured `(prompt|response|tool . …)` list · nil (buffer/region content). Returns the FSM (§3); never blocks. `:context` = opaque caller data in INFO. `:schema` (elisp plist / JSON string / `"key1, key2 type: description"` shorthand DSL; array roots wrapped in `{items: …}`) forces JSON via `gptel--parse-schema` — native modes where available, ersatz tool elsewhere (§8.2). Callback contract §3; hooks §9.2. Third parties resume paused tool rounds by invoking the CONTINUE-FN closures from `(tool-call …)` with each call's result.

### 9.4 Overlay inventory

## 10. Testing architecture (keep these seams)

1. Prompt construction is pure (buffer text + properties + config → messages): golden-file snapshots per backend (markdown & org; branching, regions, bounds restore, tool blocks).
2. Response parsing is pure over bytes: real filter/sentinel code over recorded verbatim HTTP transcripts (headers included; + synthetic `(uuid . N)` trailer) in dead process buffers; assert callback event sequences.
3. md→org: identical output whole vs arbitrarily chunked.
4. Persistence: exact property/position round-trips.
5. Config propagation: `:dry-run` FSMs expose payloads without network. Dummy backends via raw struct constructors.

## 11. Design rationale index (non-normative recap — authority is each cited section)

Text properties for roles (§2.5) over prefixes/markers/regexps: copy-surviving, zero syntax, pure reconstruction (P2) · FSM (§3) over callback chains: pause/resume, pluggable handlers, trail · prompt-buffer copy + snapshot (§4) over in-place transforms: sandboxing, request immunity (NFR-4) · curl + stdin config + write-out token (§5.2) over url.el-only/argv/temp files: streaming, cancel, demux, no argv limits, hidden keys · models as symbols (§2.2) over structs: `setq` ergonomics, no second map · cl-generic on structs (§6) over monoliths: minimal per-dialect diffs, inheritance · overlays for region context (§2.6) over position lists: edit-tracking, evaporation, doubles as highlight · rewrite preview via overlay display (§8.3) over buffer insertion: unmodified until accept · streaming md→org withholding closure (§8.4) over convert-at-end: chunking invariance while streaming · org per-heading advice+let (§8.4) over setq-local: one-request scope, no persistence · oneshot via symbol plist + `run-at-time 0` (§8.5) over direct restore: escapes lets, save-once guard · tool records as readable blocks (§8.2) over hidden tables: replay from text (P2) · Responses `store:false` (§7.2) over server threads: buffer = single source of truth (P2) · SigV4 via curl (§7.7) over elisp SigV4: crypto outsourced, hard version gate accepted · `nosystem` fallbacks (§8.1/8.3) over erroring: uniform UX across model quirks (P4) · ersatz `response_json` tool (§8.2) over refusing schema on Anthropic: one structured-output API across dialects (FR-API-3).

## 12. Known debts — deviations from stated requirements; fix or consciously inherit

Async transform completion is a counter, not a chain (race-prone; noted at FR-API-4) · HTTP 100-then-error treated as success (violates FR-NET-6) · OpenAI constructor host-sniffing silently overrides FR-BACKEND-1's constructor split, breaks behind proxies (noted at FR-BACKEND-1) · directory context entries derive MIME from the directory name, not the file (noted at FR-CTX-3) · context inspector doesn't render `:bounds`/`:lines` specs (gap vs FR-CTX-7) · Bedrock streaming discards reasoning (exception to FR-REASON-3) · MIME capability matching exact, no `image/*` globs (noted at FR-CTX-3) · variant navigation binds P and N to the same command (breaks half of FR-VAR-2) · two simultaneously selected same-named tools from different MCP servers collide in the outgoing payload — providers key tools by bare name (noted at FR-TOOL-10) · id-less backends (Gemini/Ollama) cannot disambiguate parallel same-name tool calls (noted at §7.4) · Bedrock's `toolChoice` carries a stray-quote encoding bug — `{"any":{"quote":{}}}` instead of `{"any":{}}` (noted at §7.7) · a shown tool-menu category cannot be re-collapsed by its key.
